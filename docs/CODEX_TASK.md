# 커플앱 Codex 단계별 실행 계획

> **원칙:** 한 번에 **티켓 하나**만 구현한다. `docs/PRD.md`의 해당 연결 요구사항만 참조한다. 이미 완성된 기능은 재작성하지 않는다. 각 티켓 후 사용자에게 변경 파일·검증·남은 문제를 간결히 보고한다.

## 시작 전에

1. 프로젝트 문서 위치는 `docs/PRD.md`와 `docs/CODEX_TASK.md`다. 원본 Android 앱·소스는 없으며 제공 스크린샷을 참고해 새 앱 기능을 구현한다. 기존 Android 데이터 이관은 하지 않는다.
2. 현재 프로젝트 최상위 `AGENTS.md`에 기존 기능 보존·관련 파일 우선 탐색·짧은 결과 보고 지침을 둔다.
3. 실행 원본 Android 앱은 없지만 신규 React Native 프로젝트 코드가 존재한다. 실제 기능·라이브러리·저장 방식을 말하기 전에 00단계에서 현재 프로젝트 코드를 확인한다.
4. 작업 전 변경사항을 커밋 또는 백업해 정상 상태를 확보한다.

## 00. 신규 프로젝트 현황 분석 (코드 수정 금지)

- **대상:** package.json, app.json/app.config.*, 파일 트리, 라우터, 상태 관리, 데이터 저장소, 아이콘/폰트, 알림/잠금 구현.
- **완료 조건:** 5탭 및 각 기능별 `완료/일부 구현/미구현` 표, 핵심 파일 경로, iOS 전환 위험, 테스트 스크립트 확인. 기존 Android 데이터 이전은 해당 없음.
- **Codex 요청문:**

> React Native + Expo 커플앱 현황을 코드 수정 없이 감사해 줘. `docs/PRD.md`의 2~6장 기능을 기준으로 5개 탭별 완료/일부 구현/미구현을 구분하고 관련 파일 경로, 현재 데이터 저장 방식, 사용 중인 아이콘·폰트·알림·잠금 라이브러리, Android/iOS 구현 위험을 확인해. 실제 Android 앱은 없으며 기존 데이터 이관은 하지 않으니 이관 위험은 조사하지 마. 관련 파일부터 읽고 필요할 때만 탐색을 확대해. 결과는 표와 우선 위험 5개 이하로 보고해. 어떤 파일도 수정하지 마.
