# 모바일 화면과 커플 공유 건강기록 구현

> 2026-10-29 환경 관리 변경: 아래 소스 직접 키 입력 안내는 대체되었습니다. 로컬 값은 저장소 루트 `config/env/.env.dev`/`.env.prod`에 두고 GitHub Environment Secret을 사용합니다. 최신 실행·설정은 [개발 인수인계](07-developer-handoff.md)를 따르세요.

검증일: 2026-10-29. 운영 프로젝트에는 접속하거나 변경하지 않았습니다.

## 결과

- `apps/mobile`: 기존 화면의 검정/차콜 배경, 로즈 핑크, 둥근 카드를 참고한 새 로그인·가입·커플 연결·건강 기록 화면.
- 이메일 로그인/가입, 보안 세션 저장·복원·갱신, 초대 생성/복사/폐기/수락, 커플 종료까지 Supabase 연결 코드 구현.
- 공개 Supabase URL과 publishable key는 루트 `config/env/.env.dev`/`.env.prod`에서 주입. 소스에는 비밀 관리자 키를 입력하지 않음.
- 건강 날짜·증상·기분·메모·생리 기간은 커플 공유 데이터. 같은 커플 구성원은 작성자와 관계없이 조회/추가/수정/삭제 가능.
- 서버 RLS로 다른 커플·미인증·탈퇴 사용자의 접근 차단. 작성자/수정자 및 version은 서버가 관리하며 앱에서 위조할 수 없음.
- 중복 날짜/겹치는 기간 차단, 동시에 수정한 기록은 덮어쓰지 않고 새로고침 안내.
- 마지막 구성원이 탈퇴하면 커플의 건강 기록도 삭제. 앱에서 확인 문구 제공.

## 적용 방법과 사용자 확인 사항

1. 새 Supabase 프로젝트에 `20261026000100_auth_couple.sql`, `20261027000100_shared_health.sql`을 순서대로 적용합니다. 원본은 `spikes/auth-couple-poc/supabase/migrations/`에 있습니다. 이미 사용 중인 스키마에는 비교 없이 실행하지 않습니다.
2. `config/env/.env.dev`에 개발 Project URL과 `sb_publishable_...` 공개 키를 입력합니다.
3. 이메일 가입/메일 확인과 실제 발송용 SMTP를 설정합니다.
4. 앱을 다시 실행하여 두 계정으로 로그인 → 초대 연결 → 한쪽에서 건강기록 작성 → 다른 쪽에서 조회·수정·삭제를 확인합니다.

상세 실행 절차는 `apps/mobile/README.md`에 있습니다.

## 범위와 남은 작업

- 건강 달력은 커플당 하나이며 사용자별 생리 달력은 분리하지 않습니다.
- 상대방 변경은 화면 재진입/새로고침/앱 복귀 시 조회합니다. Realtime/오프라인 저장은 포함하지 않습니다.
- 일반 일정·일기/사진 화면은 다음 구현 대상입니다. 현재 탭에 해당 상태를 표시합니다.
- 위젯은 별도 PoC이며 새 모바일 앱의 운영 데이터와 아직 통합하지 않았습니다. 건강 데이터는 위젯/알림에 전달하지 않습니다.
- 키 입력만으로 스토어 배포가 완료되지는 않습니다. 실제 앱 식별자, 서명, 메일 설정, 실기기 점검이 필요합니다.
- 앱 비활성 시 화면을 가리는 처리는 추가했으나 OS 앱 전환기 캡처 차단을 보장하는 네이티브 보안 기능은 아닙니다.

## Android 재검증

개발 빌드에서 스크립트를 불러오지 못하는 실행 오류를 확인했습니다. 개발 서버에 의존하지 않는 release 변형을 별도로 빌드하여 Galaxy S24 FE AVD(Android 17/API 37.1)에 설치·실행했습니다. `BUILD SUCCESSFUL` 및 앱의 `2026-10-26 D+299` 갱신 요청 완료를 확인했습니다. 증거는 `spikes/widget-poc/logs/android-release-recheck.log`, `android-refresh.png`입니다. 이 APK는 로컬 테스트 서명이며 스토어 배포용 서명이 아닙니다.

앱 의존성 검사 결과는 `apps/mobile/logs/dependency-audit.json`에 보관했습니다. Expo 도구 및 하위 의존성 경고가 남아 있으며 강제 주요 버전 변경은 적용하지 않았습니다. 스토어 배포 전 호환 버전 업데이트와 재검증이 필요합니다.

Android에서 두 위젯 제공자의 OS 등록과 앱 갱신 요청 완료까지 확인했습니다. 화면 제어 도구의 Home/터치 입력이 일관되게 반영되지 않아, **홈 화면에 두 위젯을 배치한 최종 표시와 글자 잘림 여부는 아직 미확인**입니다. 등록·갱신 요청 성공을 홈 위젯 표시 성공으로 판정하지 않았습니다. 직접 확인 시 `Couple Widget PoC`에서 갱신 → 홈 빈 곳 길게 누르기 → 위젯 → `우리의 D-Day`와 `이번 달 일정` 추가 순서로 확인하세요. 고정 날짜는 D+299, 2026-10-29 서울 날짜는 D+302가 기준입니다. 실제 Samsung One UI 기기 검증도 별도로 필요합니다.
