## 실제 자료와 확실성

작업 루트에는 `couple_codex_starter/README.md`, `CODEX_FIRST_TASK.md`, 숨김 메타데이터와 참고 JPG 8개가 있다. 원본 앱 소스, APK, Gradle, Flutter pubspec, 기존 JS 프로젝트, DB, AGENTS.md는 발견되지 않았다. 이후 생성된 `spikes/widget-poc/`는 새 실험이므로 기존 앱의 기술 스택 증거가 아니다. 단말 로컬 저장이라는 설명은 사용자 제공 정보이며 SQLite/Room/SharedPreferences/AsyncStorage 중 무엇인지는 미확인이다.

실제 이미지 위치는 `.gitignore/docs/references/private/`다. `.gitignore`가 **파일이 아닌 디렉터리**이고 이 루트는 Git 저장소가 아니다. 따라서 무시 규칙이 설정된 상태가 아니다. 기존 경로는 변경하지 않았다. 향후 저장소 초기화 전 이미지를 저장소 밖으로 이동하고 정상적인 `.gitignore` 파일을 별도로 마련한 후 `git check-ignore`와 추적 목록을 확인해야 한다. 현재 루트에서 `git add .` 또는 원격 업로드를 해서는 안 된다.

## 전환 후보 (모두 추정)

- 하단 `홈 / 달력 / 마법 / 기록 / 설정` → Expo Router 탭 구조 후보.
- 홈 관리 → 기념일 관리 화면 또는 모달; 캘린더 + → 선택 날짜가 채워진 일정 폼.
- 02→03, 04→05, 07→08은 같은 탭의 세로 스크롤일 가능성이 높으며 별도 라우트로 확정하지 않는다.
- 일기 카드 → 상세, + → 작성, 위시리스트/선물 메모 → 기록 탭 내부 필터 후보.
- 마법 시작 → 시작일 기록/종료 모드 전환 후보. 종료 동작은 사용자 설명에만 있고 이미지에서 직접 확인하지 못했다.

## 보존할 UI와 바꿀 개인정보 기본값

블랙/차콜 배경, 로즈 핑크·버건디 강조, 큰 둥근 카드, 둥근 칩, 넓은 숫자, 고정 하단 5개 탭을 보존한다. 정확한 색상·폰트·간격은 소스가 없으므로 시각적 근사다. 작은 화면·큰 글씨·스크린리더와 iOS 안전영역은 별도 검증한다.

화면의 '마법'은 기능 문서에서 **개인 생리·주기 기록**으로 정의한다. 기존 달력의 표시를 그대로 서버 공유 데이터에 섞지 않는다. 본인만 조회한 건강 기록을 앱 안에서 선택적으로 합성하는 비공개 오버레이로 구현한다. 스크린샷의 토글 상태는 새 앱의 초기값이 아니다.

## 기존 프로젝트 활용 대안

| 자료 확보 상황 | 재사용 가능 | 제한·리스크 |
|---|---|---|
| 현재처럼 이미지만 존재 | 정보 구조·화면 톤·요구사항 | 동작·저장 구조 검증 불가, 실행 코드 재사용 없음 |
| APK만 확보 | 설치 후 동작 확인, 허가된 리소스·매니페스트 조사 | APK로 iOS 앱 생성 불가; 복원 코드는 원본과 동등하지 않음; 단말 개인 DB 자동 추출 불가 |
| Kotlin/Java 소스 확보 | 규칙·리소스·데이터 변환 정의, Android 네이티브 일부 | RN UI 재작성, iOS 별도 대응 |
| Flutter 소스 확보 | 기존 Flutter로 양 OS 확장 가능성, Dart 규칙 참고 | RN으로 옮기면 Dart UI 직접 재사용 불가; Flutter 유지안과 비용 비교 필요 |
| RN/Expo 소스 확보 | TS/JS 규칙·컴포넌트 일부 | 기존 의존성·권한·저장 모델 감사를 거친 후 판단 |
